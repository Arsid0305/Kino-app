# Lessons

## [2026-07-11] OTP-код — ровно 8 цифр (не 6)

**Что произошло:** серия из ≥5 подряд коммитов чинила «OTP не проходит» / «длина не совпадает».
**Правило:** в Supabase Auth конфиге OTP-код настроен на **8 цифр** (не дефолтные 6). Валидация во фронте / регексы / плейсхолдеры инпутов — под 8. При изменении длины — искать все `.{6}` / `length === 6` / `maxLength={6}` в `src/pages/Index.tsx` и компонентах auth.

## [2026-07-11] iOS status bar — учитывать safe-area-inset-top

**Что произошло:** серия коммитов правила overlap контента с системным статус-баром на iOS в модальных диалогах.
**Правило:** любая полноэкранная модалка / drawer / fullscreen-overlay в мобильном режиме — оборачивать в контейнер с `padding-top: env(safe-area-inset-top)` или Tailwind `pt-[env(safe-area-inset-top)]`. Проверять на реальном iOS Safari, а не в Chrome DevTools iPhone-эмуляции.

## [2026-07-11] Watchlist highlight — derived state, не ручной setState

**Что произошло:** пункт watchlist подсвечивался неверно после смены фильтра.
**Правило:** если UI-состояние (highlight, selected, active) зависит от нескольких источников (list + activeFilter + currentTab) — держать derived state через `useMemo` из явных источников, не в `useState` с ручными `setState`. Проверять с пустым списком и при переключении фильтра туда-обратно.

## [2026-07-11] CORS fallback на `*` — регресс безопасности

**Что произошло:** edge-функции содержали `if (allowed.length === 0) return "*"` — если secret `ALLOWED_ORIGINS` снесён, любой Origin проходит.
**Правило:** никогда fallback на wildcard в CORS. Hardcoded whitelist в коде + secret как override. Валидация непустоты secret — шаг в CI.

## [2026-08-16] Фикс дефолта — искать источник значения, а не место, где оно используется

**Что произошло:** утром сменила дефолт AI-провайдера на бэке `claude` → `gpt4o`, отчиталась «починено». К вечеру аудит показал: чат по-прежнему падает на Anthropic. Причина — фронт при пустом localStorage всегда шлёт валидное `'claude'` (`AiAdvisor.tsx:140`), а бэк подставляет дефолт только когда `provider` невалиден или отсутствует. Мой фикс никогда не срабатывал.
**Правило:** при фиксе «дефолтного» значения — сначала посмотреть, кто это значение отправляет. Дефолт на приёмной стороне защищает от отсутствующего/сломанного клиента, а не от клиента с явным устаревшим выбором. Проверять чистым окном инкогнито, а не своим браузером с сохранённым состоянием.

## [2026-08-16] Один провайдер = одна точка отказа

**Что произошло:** `movie-recommendation` вызывала только DeepSeek. Когда провайдер снял `deepseek-chat` 24 июля, подбор молча пролежал больше месяца — заменить его было нечем. У `ai-chat` четыре провайдера, у подбора ноль запасных.
**Правило:** если промпт можно повторить в другом OpenAI-совместимом API (или даже с небольшой адаптацией) — фолбэк ставить сразу, не ждать инцидента. Один живой ключ (любой) должен быть достаточным условием, чтобы функция работала.

_Уточнено (2026-11-15): правило менялось дважды, актуальная версия — урок «[2026-09-04] Выбор провайдера и фолбэк — решение владелицы, не молчаливый дефолт» ниже._

## [2026-08-16] `error.message` от апстрима — утечка внутренних данных клиенту

**Что произошло:** обе edge-функции отдавали наружу `error.message`, а он собирался как `${baseUrl} ${res.status}: ${await res.text()}` — то есть тело ответа провайдера уходило в браузер. При 401/429 туда бывают id организации, тип ключа, остатки квоты.
**Правило:** тело ответа апстрима — только в `console.error` (обрезать до 500 символов). Клиенту — обобщённое сообщение и HTTP-код. Общий catch тоже возвращает не `error.message`, а фиксированную строку.

## [2026-08-16] Rate limit fail-open на платные вызовы = дыра в квоте

**Что произошло:** `checkRateLimit` при ошибке БД возвращала `true` (пропустить). Отказ таблицы `rate_limits` снимал лимит на платные LLM-вызовы.
**Правило:** для платных ресурсов — fail-closed. Один упавший запрос лучше, чем открытая дверь на списание квоты. Fail-open допустим только для бесплатных / читающих операций, где отказ ломает UX сильнее, чем перерасход.

## [2026-08-16] Молчаливое обрезание списка вместо ошибки

**Что произошло:** `fetchAllUserMovieRows` останавливалась на `MAX_PAGES=40` без сигнала — библиотека > 20 000 записей молча резалась. Тот же класс бага, что чинили с `limit(500)`: пользователь видит неполный список и не знает об этом.
**Правило:** при достижении «безопасного потолка» — бросать ошибку, а не возвращать неполные данные. Пользователь видит проблему явно и может расширить потолок или почистить лишнее.

## [2026-08-16] Общий Supabase-инстанс = чужие миграции в `applied`-списке

**Что произошло:** аудит показал 4 миграции в БД без файлов в git. Проверка — 3 из них в схеме `technical_language`, это другой проект на том же инстансе. Только одна (`create_rate_limit_function`) действительно из Kino-app и была применена вручную через SQL Editor.
**Правило:** перед бэкфиллом миграций из проды в git — проверить схему. `SELECT statements` из `supabase_migrations.schema_migrations` показывает, к какой схеме они относятся. Не тащить чужое в свой репо.

## [2026-08-16] «Аудит показал 47 проблем» — 90% уже неактуальны

**Что произошло:** ревьюер выдал длинный список находок; половина оказалась про правки, сделанные ранее в той же сессии, ещё несколько — про несуществующие домены Vercel, ещё несколько — теоретические риски без данных в базе.
**Правило:** после ревью — быстрый sanity-check по фактам: sql-запросы на реальную базу, git-status изменений, реальные домены. Не тащить в отчёт находки, которые опровергаются одним запросом.

## [2026-08-17] «Мерж локального в облако при синке» = обратный поток данных

**Что произошло:** `Index.tsx` при заходе мержил cloudLibrary с localStorage и заливал разницу обратно через `seedCloudLibrary`. Удалённое на устройстве A воскресало на устройстве B — B видел фильм в своём кеше, не видел в облаке, заливал.
**Правило:** если облако — источник правды, локальный кеш должен быть **read-only копией**. Только явные операции (add/rate/delete) пишут в облако, синк только читает. Двунаправленный синк без версионирования (тумбстоуны / vector clocks / last-write-wins с timestamp) невозможен: «отсутствует в облаке» и «удалён из облака» неотличимы. Слепая ветка «облако пустое → залить локальное» — тот же баг: воскрешает всё, что пользователь чистил в облаке.

## [2026-08-29] PostgREST видит только схему `public` — RPC в `kino` падает молча

**Что произошло:** edge-функции звали `supabaseAdmin.rpc('check_and_increment_rate_limit', …)`. Функция была только в `kino`, а PostgREST по умолчанию открывает только `public`. Каждый RPC возвращал «function not found». Пока `checkRateLimit` был fail-open, ошибка маскировалась. После переключения на fail-closed (16.08) каждый чат стал возвращать 429 на первом же запросе — таблица `kino.rate_limits` при этом оставалась пустой.
**Правило:** любая функция, которую зовут из edge через `rpc()`, должна лежать в `public` — либо тонкая обёртка `public.f(...)`, возвращающая `SELECT kino.f(...)`, с `SECURITY DEFINER` и `GRANT EXECUTE` только `service_role` (сейчас так: миграции `20260829141000_expose_rate_limit_in_public.sql` и `20261001180000_revoke_rate_limit_from_clients.sql`). Проверка: если `kino.rate_limits`/аналог пустой, а трафик есть — RPC не долетает, смотреть схему функции. При переходе fail-open → fail-closed обязательно прогнать один живой запрос и увидеть запись в таблице.

## [2026-08-29] LLM выдумывает год фильма — dedup по (title+year) пропускает

**Что произошло:** модель предлагала «Завтрак у Тиффани 2018» — фильма с таким годом не существует, настоящий 1961. У пользователя реальный 1961 уже в `watched` с оценкой 8. `getMovieDedupKey = titleRu::year::type` посчитал их разными фильмами, галлюцинация попала в watchlist и всплывала снова. В базе нашлось 5 таких пар.
**Правило:** для чёрного списка LLM-рекомендаций сравнение по названию — **без года и типа** (lowercase, trim, схлопнутые пробелы). `getMovieDedupKey` остаётся вторым барьером. Для данных Кинопоиска год важен (римейки, тёзки), для LLM — нет: галлюцинация года дороже случайного совпадения по имени. Сделано в PR #74.

## [2026-08-29] Клиент режет контекст → сервер должен фильтровать по полному списку

**Что произошло:** в промпт уходила только часть просмотренного (тогда 30 для чата и 80 для подбора из 594). Пост-фильтр на сервере строился из той же части, поэтому всё вне окна модель могла предложить повторно.
**Правило:** если промпт сокращён — пост-фильтр получает **отдельно полный список** (лёгкий `string[]` названий). Клиент шлёт `forbiddenTitles`, сервер фильтрует ответ по нему (сейчас лимит 2000 в `supabase/functions/_shared/input.ts`). В промпт идёт сокращённая выборка, но фильтрация обязана быть полной.

## [2026-09-04] Выбор провайдера и фолбэк — решение владелицы, не молчаливый дефолт

**Что произошло:** правило про запасного провайдера менялось трижды. 16.08 — «фолбэк ставить сразу» (урок выше). 04.09 владелица спросила «через что рекомендует?» и выяснилось, что подбор молча уходит с DeepSeek на OpenAI, выбрать провайдера нельзя — в PR #75 появился выбор провайдера на главной. В PR #80 (октябрь) по согласованию вернули цепочку как в WB-Bot: выбранный провайдер + 1 повтор, затем `deepseek → gpt4o → gemini → claude` (`supabase/functions/_shared/llm.ts`, `callWithFallback`).
**Правило:** не менять платного провайдера и схему фолбэка молча — только по явному решению владелицы, с понятными расходами. Если фолбэк есть, пользователь должен видеть, кто ответил: сервер уже возвращает `provider` в ответе подбора, но на экране он пока не показывается (на 2026-11-15). При правке фолбэка сверяться с последним решением (сейчас — PR #80), а не с ранними уроками.

## [2026-09-04] Vercel-токен слетает — перелогиниться, CLI не обновлять из скрипта

**Что произошло:** `scripts/deploy.ps1` (сейчас запасной ручной путь, основной — автодеплой Vercel из `main`) упал на `Error: Not authorized` от Vercel — сессия истекла. Автообновление CLI дополнительно упало (`spawn npm ENOENT` — npm не в PATH), но это отвлечение.
**Правило:** при `Not authorized` — `vercel login`, вход через **Continue with Email** проверен. Не обновлять CLI из скрипта: `npm` вне PATH текущей PowerShell-сессии — отдельная проблема, деплой не блокирует. _Причина «GitHub-вход упрётся в T&S-флаг» устарела: флаг снят 2026-09-27._

## [2026-09-06] Отчёт не заменяет завершение сессии

**Что произошло:** аудит был сохранён в PR, но задачи не перенесены в todo; понадобилось напоминание владелицы об уже существующем порядке.
**Правило:** до работы читать системные файлы и правила проекта; при завершении обновлять todo, связывать задачи с находками и критериями готовности, дополнять lessons без дублей. «Записано» не означает «исправлено». Уроки и задачи не держать только в долгоживущей PR-ветке: такой PR быстро конфликтует с `main`, и уроки теряются (так было с PR #77 и #79, перенесены 2026-11-15).

## [2026-09-06] Зелёная команда может ничего не проверять

**Что произошло:** корневой `tsc --noEmit` с `files: []` завершился успешно, а `--listFiles` не перечислил ни одного файла; явная проверка app-конфига прошла по 429 файлам.
**Правило:** проверять охват проверки, а не только код выхода: явные app/node-конфиги, ненулевое число тестов. Vite build не заменяет проверку TypeScript.

## [2026-09-06] Защиту определяют реальные права и реальный путь выполнения

**Что произошло:** `REVOKE ... FROM PUBLIC` оставил отдельные `EXECUTE`-права у `anon`/`authenticated`; RLS с условием `true` не изолировала старые данные. Workflow напрямую вызывал merge, хотя встроенный автомерж GitHub был выключен.
**Правило:** проверять права каждой роли, условия политик, доступность API и фактический путь выполнения. Наличие RLS, слово «own» в названии политики или выключенная настройка не доказывают защиту. Проверять безопасно, без настоящего вредоносного PR/RPC.

## [2026-09-06] Облачный источник правды требует подтверждённых записей

**Что произошло:** интерфейс и кеш обновлялись до успеха записи; импорт не ждал ответа; очистка чата игнорировала ошибку, которую вернул Supabase. Следующая синхронизация могла отменить неподтверждённую правку.
**Правило:** различать оптимистичное и подтверждённое состояние: ждать Promise, проверять `{ error }`, откатывать или явно показывать «не сохранено». Тестировать отказ сети и смену аккаунта; кеш привязывать к `user.id`. Дополняет урок 17.08, двунаправленную синхронизацию не возвращает.

## [2026-09-06] Ограничения должны совпадать на границах системы

**Что произошло:** клиент отправлял всю историю чата при серверном лимите 20; разные нормализаторы пропускали повторы и искажали типы при импорте; служебная «пустая» дата попадала в свежие вкусы.
**Правило:** одни правила нормализации и проверки схемы на входе и выходе (сейчас zod в `supabase/functions/_shared/input.ts`); контекст ограничивать без удаления истории, неизвестную дату отличать от реальной. Проверять граничные и повреждённые данные. Молчаливое обрезание разобрано в уроке 16.08.

## [2026-09-06] Старый инцидент не является текущим статусом сервиса

**Что произошло:** после того как владелица подтвердила снятие блокировки GitHub, инструкции продолжали считать отсутствие запусков признаком блокировки.
**Правило:** у любого статуса указывать дату и источник; отсутствие запусков не доказывает блокировку, а недоступный для проверки Vercel не значит, что сайт упал. Повторные запросы разрешений не обходят отказ владелицы.
