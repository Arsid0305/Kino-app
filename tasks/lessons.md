# Lessons

## [2026-09-06] Отчёт не заменяет завершение сессии

**Что произошло:** аудит был сохранён в PR, но задачи не перенесены в ToDo; потребовалось напоминание пользователя об уже существующем алгоритме.
**Правило:** до работы читать системные файлы и проектные правила; при завершении обновлять актуальный контекст ToDo, связывать задачи с находками и критериями готовности, дополнять lessons без дублей. «Записано» не означает «исправлено». Если пользователь оставляет мерж для Claude, сохранять в той же PR-ветке и явно передавать её следующей сессии, не мержить ради доступности в main.

## [2026-09-06] Зелёная команда может ничего не проверять

**Что произошло:** корневой `tsc --noEmit` с files:[] завершился успешно, а `--listFiles` не перечислил файлов; явный app-check проверил 429 файлов.
**Правило:** проверять охват gate, а не только exit code: явные app/node configs, ненулевое число тестов; Vite build не заменяет TypeScript-check. Основание: аудит N08.

## [2026-09-06] Защиту определяют эффективные права и механизм действия

**Что произошло:** REVOKE у PUBLIC оставил отдельные EXECUTE-grants anon/authenticated; RLS с условием true не изолировала старые данные. Workflow напрямую вызывал merge, независимо от ожидания native auto-merge.
**Правило:** проверять ACL каждой роли, условия policies, доступность API и фактический путь исполнения. Наличие RLS, название «own» или выключенная настройка native auto-merge не доказывают защиту. Основание: N01/N03/N04; проверять безопасно, без реального вредоносного PR/RPC.

## [2026-09-06] Облачный источник правды требует подтверждённых записей

**Что произошло:** UI/cache обновлялись до успеха записи; импорт не ожидал callback; очистка чата игнорировала возвращённый Supabase error. Следующий sync мог отменить неподтверждённую правку.
**Правило:** различать optimistic и подтверждённое состояние, ожидать Promise, проверять `{error}`, делать rollback либо явно показывать несохранённое. Тестировать сетевой отказ и смену аккаунта; кеш привязывать к user.id. Дополняет урок 17.08, не возвращает двунаправленный sync. Основание: N06/N10/N11.

## [2026-09-06] Ограничения должны совпадать на границах системы

**Что произошло:** клиент отправлял всю историю при серверном лимите 20; разные нормализаторы пропускали повторы и искажали типы импорта; sentinel-дата попадала в свежие вкусы.
**Правило:** единые правила нормализации и runtime-схемы входа/выхода; контекст ограничивать без удаления истории, неизвестную дату отличать от реальной. Проверять границы и повреждённые данные. Основание: N05/N09/N12–N14; молчаливое обрезание уже разобрано в уроке 16.08.

## [2026-09-06] Старый инцидент не является текущим статусом сервиса

**Что произошло:** после подтверждённого пользователем снятия GitHub-бана инструкции продолжали считать отсутствие runs признаком блокировки.
**Правило:** указывать дату и источник статуса; отсутствие запусков не доказывает бан, а недоступный для проверки Vercel не означает падение сайта. Повторные проверки разрешений не обходят отказ пользователя. Основание: N16 и границы аудита.

## [2026-09-06] Уточнение урока про обязательный fallback

**Что произошло:** правило 16.08 «фолбэк ставить сразу» противоречит осознанному выбору провайдера в PR #75.
**Правило:** отказ показывать явно; не менять платного провайдера молча. Fallback допустим только как отдельно согласованное поведение с понятными расходами. Старый урок ниже сохраняется как история, это уточнение имеет приоритет.

## [2026-07-11] OTP-код — ровно 8 цифр (не 6)

**Что произошло:** серия из ≥5 подряд коммитов чинила «OTP не проходит» / «длина не совпадает».
**Правило:** в Supabase Auth конфиге OTP-код настроен на **8 цифр** (не дефолтные 6). Валидация во фронте / регексы / плейсхолдеры инпутов — под 8. При изменении длины — искать все `.{6}` / `length === 6` / `maxLength={6}` в `src/pages/Index.tsx` и компонентах auth.

## [2026-07-11] iOS status bar — учитывать safe-area-inset-top

**Что произошло:** серия коммитов правила overlap контента с системным статус-баром на iOS в модальных диалогах.
**Правило:** любая полноэкранная модалка / drawer / fullscreen-overlay в мобильном режиме — оборачивать в контейнер с `padding-top: env(safe-area-inset-top)` или Tailwind `pt-[env(safe-area-inset-top)]`. Проверять на реальном iOS Safari, а не в Chrome DevTools iPhone-эмуляции.

## [2026-07-11] Watchlist highlight — derived state, не ручной setState

**Что произошло:** пункт watchlist подсвечивался неверно после смены фильтра.
**Правило:** если UI-состояние (highlight, selected, active) зависит от нескольких источников (list + activeFilter + currentTab) — держать derived state через `useMemo` из явных источников, не в `useState` с ручными `setState`. Проверять с пустым списком и при переключении фильтра туда-обратно.

## [2026-07-11] CORS fallback на `*` — регресс безопасности

**Что произошло:** edge-функции содержали `if (allowed.length === 0) return "*"` — если secret `ALLOWED_ORIGINS` снесён, любой Origin проходит.
**Правило:** никогда fallback на wildcard в CORS. Hardcoded whitelist в коде + secret как override. Валидация непустоты secret — шаг в CI.

## [2026-08-16] Фикс дефолта — искать источник значения, а не место, где оно используется

**Что произошло:** утром сменила дефолт AI-провайдера на бэке `claude` → `gpt4o`, отчиталась «починено». К вечеру аудит показал: чат по-прежнему падает на Anthropic. Причина — фронт при пустом localStorage всегда шлёт валидное `'claude'` (`AiAdvisor.tsx:140`), а бэк подставляет дефолт только когда `provider` невалиден или отсутствует. Мой фикс никогда не срабатывал.
**Правило:** при фиксе «дефолтного» значения — сначала посмотреть, кто это значение отправляет. Дефолт на приёмной стороне защищает от отсутствующего/сломанного клиента, а не от клиента с явным устаревшим выбором. Проверять чистым окном инкогнито, а не своим браузером с сохранённым состоянием.

## [2026-08-16] Один провайдер = одна точка отказа

**Что произошло:** `movie-recommendation` вызывала только DeepSeek. Когда провайдер снял `deepseek-chat` 24 июля, подбор молча пролежал больше месяца — заменить его было нечем. У `ai-chat` четыре провайдера, у подбора ноль запасных.
**Правило:** если промпт можно повторить в другом OpenAI-совместимом API (или даже с небольшой адаптацией) — фолбэк ставить сразу, не ждать инцидента. Один живой ключ (любой) должен быть достаточным условием, чтобы функция работала.

## [2026-08-16] `error.message` от апстрима — утечка внутренних данных клиенту

**Что произошло:** обе edge-функции отдавали наружу `error.message`, а он собирался как `${baseUrl} ${res.status}: ${await res.text()}` — то есть тело ответа провайдера уходило в браузер. При 401/429 туда бывают id организации, тип ключа, остатки квоты.
**Правило:** тело ответа апстрима — только в `console.error` (обрезать до 500 символов). Клиенту — обобщённое сообщение и HTTP-код. Общий catch тоже возвращает не `error.message`, а фиксированную строку.

## [2026-08-16] Rate limit fail-open на платные вызовы = дыра в квоте

**Что произошло:** `checkRateLimit` при ошибке БД возвращала `true` (пропустить). Отказ таблицы `rate_limits` снимал лимит на платные LLM-вызовы.
**Правило:** для платных ресурсов — fail-closed. Один упавший запрос лучше, чем открытая дверь на списание квоты. Fail-open допустим только для бесплатных / читающих операций, где отказ ломает UX сильнее, чем перерасход.

## [2026-08-16] Молчаливое обрезание списка вместо ошибки

**Что произошло:** `fetchAllUserMovieRows` останавливалась на `MAX_PAGES=40` без сигнала — библиотека > 20 000 записей молча резалась. Тот же класс бага, что чинили с `limit(500)`: пользователь видит неполный список и не знает об этом.
**Правило:** при достижении «безопасного потолка» — бросать ошибку, а не возвращать неполные данные. Пользователь видит проблему явно и может расширить потолок или почистить лишнее.

## [2026-08-16] Общий Supabase-инстанс = чужие миграции в `applied`-списке

**Что произошло:** аудит показал 4 миграции в БД без файлов в git. Проверка — 3 из них в схеме `technical_language`, это другой проект на том же инстансе. Только одна (`create_rate_limit_function`) действительно из Kino-app и была применена вручную через SQL Editor.
**Правило:** перед бэкфиллом миграций из проды в git — проверить схему. `SELECT statements` из `supabase_migrations.schema_migrations` показывает, к какой схеме они относятся. Не тащить чужое в свой репо.

## [2026-08-16] «Аудит показал 47 проблем» — 90% уже неактуальны

**Что произошло:** ревьюер выдал длинный список находок; половина оказалась про правки, сделанные ранее в той же сессии, ещё несколько — про несуществующие домены Vercel, ещё несколько — теоретические риски без данных в базе.
**Правило:** после ревью — быстрый sanity-check по фактам: sql-запросы на реальную базу, git-status изменений, реальные домены. Не тащить в отчёт находки, которые опровергаются одним запросом.

## [2026-08-17] «Мерж локального в облако при синке» = обратный поток данных

**Что произошло:** `Index.tsx` при заходе мержил cloudLibrary с localStorage и заливал разницу обратно через `seedCloudLibrary`. Удалённое на устройстве A воскресало на устройстве B — B видел фильм в своём кеше, не видел в облаке, заливал.
**Правило:** если облако — источник правды, локальный кеш должен быть **read-only копией**. Только явные операции (add/rate/delete) пишут в облако, синк только читает. Двунаправленный синк без версионирования (тумбстоуны / vector clocks / last-write-wins с timestamp) невозможен: «отсутствует в облаке» и «удалён из облака» неотличимы. Слепая ветка «облако пустое → залить локальное» — тот же баг: воскрешает всё, что пользователь чистил в облаке.
