## Новые находки

Формат: **[серьёзность] [уверенность]**. HIGH confidence означает подтверждение кодом/метаданными/локальной проверкой, но не автоматически эксплуатацию в интернете.

### N01. Автоматический мерж без проверок и доверенного источника — [HIGH] [HIGH]

**Файл:** `.github/workflows/automerge.yml:4–28`.
Workflow делает прямой `pulls.merge`, не включает ожидающий native auto-merge. Проверяется лишь имя head-ветки и draft; нет проверки автора, репозитория head, тестов, одобрения или ожидаемого SHA.
GitHub API: `main.protected=false`, required checks пусты; найденный ruleset отключён. `allow_auto_merge=true` также установлен, но переключение только этой опции **не отключит прямой API-мерж**.
**Последствие:** подходящий PR может попасть в main без проверки; имя ветки само по себе не устанавливает доверие, включая PR из fork.
**Фикс:** по решению пользователя отключить/удалить workflow автомержа; оставить ручное слияние, настроить required checks. Не проверять опасный сценарий реальным PR.

### N02. Невалидный SHA ломает автоматический деплой — [HIGH] [HIGH]

**Файл:** `.github/workflows/deploy.yml:16`.
GitHub API для указанного SHA `supabase/setup-cli` вернул 422: commit не найден.
**Последствие:** workflow не сможет загрузить action даже после восстановления Actions.
**Фикс:** закрепить существующий, проверенный commit официального action; проверить один согласованный запуск после исправления. Пока не запускалось.

### N03. Серверные RPC доступны публичным ролям — [HIGH] [HIGH]

**Файл:** `supabase/migrations/20260829141000_expose_rate_limit_in_public.sql:12–22`; production `public/kino.check_and_increment_rate_limit`.
Чтение ACL и `has_function_privilege` подтвердило EXECUTE для anon и authenticated на обеих функциях SECURITY DEFINER. Миграция отозвала PUBLIC, но отдельные grants сохранились.
**Последствие:** вызывающий может менять служебные счётчики с параметрами, которые должен контролировать сервер; защита платных вызовов становится ненадёжной.
**Фикс:** явно отозвать EXECUTE у PUBLIC, anon, authenticated на обеих функциях, оставить service_role; сверить реальные ACL и серверный вызов. Старую `check_rate_limit` учитывать отдельно как известный долг.
Подтверждено также [Supabase Advisor](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable). RPC в production для воспроизведения не вызывались.

### N04. Старые таблицы имеют формальную, но не ограничивающую RLS — [HIGH] [HIGH]

**Объекты production:** `kino.users`, `kino.films_history`, `kino.user_settings`. Их создания нет в текущих миграциях; место добавления восстановления — `supabase/migrations/`.
Политики «own data» фактически используют `true`, применяются к PUBLIC. У anon есть USAGE схемы, SELECT и INSERT. Таблицы не пусты.
**Последствие:** на уровне БД нет изоляции этих данных по владельцу. Доступность схемы через текущий Data API отдельно не установлена; факт утечки не утверждается.
**Фикс:** установить назначение таблиц; ненужные API-grants отозвать, для нужных настроить принадлежность владельцу. Не удалять старые данные вслепую.

### N05. Чат перестаёт принимать длинную историю — [HIGH] [HIGH]

**Файлы:** `src/components/AiAdvisor.tsx:225–239`, `src/lib/chatStore.ts:71`, `supabase/functions/ai-chat/index.ts:283–297`.
Клиент отправляет всю историю, загрузчик читает до 40 сообщений; сервер разрешает 20, максимум 2000 символов на сообщение и 12000 суммарно.
**Последствие:** после 10 пар вопрос/ответ следующий запрос из 21 сообщения отклоняется; после загрузки длинной истории — сразу. Ошибки тоже дописываются в локальную историю.
**Фикс:** перед отправкой формировать окно контекста по количеству и длине, не удаляя сохранённый разговор; ограничить текущий ввод. Тесты на 19/20/21 и суммарный лимит.

### N06. «Облако — источник правды» не доведено до операций записи — [HIGH] [HIGH]

**Файл:** `src/pages/Index.tsx:158–180,226–338`; `src/components/FileUpload.tsx:39,72–78`.
Списки/state/localStorage меняются до await облачной записи. В catch только уведомление, без rollback/статуса несохранённого. FileUpload не ожидает асинхронный callback и показывает успех сразу.
**Последствие:** после сбоя сети оценка/импорт выглядит сохранённым, но следующая синхронизация перезаписывает кеш облаком и теряет неподтверждённую правку; неудачное удаление возвращается.
**Фикс:** для онлайн-режима менять подтверждённое состояние после успеха либо откатывать optimistic update. Callback импорта должен возвращать Promise и ожидаться. Не возвращать слепой cloud/local merge.

### N07. Схема БД не восстанавливается из репозитория — [HIGH] [HIGH]

**Файлы:** `supabase/migrations/20260524202941_rate_limits.sql:2–6`, `20260528123333_create_rate_limit_function.sql:2–7`, `20260816120956_security_invoker_views.sql:5–6`, `20260829141000_expose_rate_limit_in_public.sql:18`.
Две несовместимые структуры `public.rate_limits` объявлены через IF NOT EXISTS. Нет создания kino, основных таблиц, views и kino-функции, но поздние миграции обращаются к ним.
**Последствие:** новое окружение/восстановление не воспроизводит production; IF NOT EXISTS не преобразует старую структуру.
**Фикс:** согласованный baseline только объектов Kino, затем forward-миграции; проверка на отдельной чистой БД. Общий Supabase содержит другой проект — не переносить его объекты. Чистая БД в этом аудите не создавалась.

### N08. Защита TypeScript в ручном деплое фиктивна — [HIGH] [HIGH]

**Файлы:** `scripts/deploy.ps1:105`, `tsconfig.json:2–9`.
Корневой config содержит `files:[]` и references. Обычный `tsc --noEmit` не обходит referenced projects; `--listFiles` подтвердил пустой результат. Настоящая проверка app перечисляет 429 файлов.
**Последствие:** надпись «tsc чисто» не защищает деплой.
**Фикс:** явно проверять app и node configs, добавить lint; Edge Functions проверять отдельно. Сейчас app-тайпчек проходит — это дефект проверки, а не обнаруженная ошибка типов.

### N09. Внешние ответы и часть входных данных не валидируются — [HIGH] [HIGH]

**Файлы:** `supabase/functions/ai-chat/index.ts:305–345,469–493`, `movie-recommendation/index.ts:288–326`, `src/components/AiAdvisor.tsx:94–109`.
Известный TODO про zod подтверждён конкретными случаями: null в списке фильмов даёт 500; null-рекомендация ломает обработку; строка вместо genre-массива может дойти до UI с вызовом map. Нет общего лимита тела и длин названий/filters/forbiddenTitles.
**Последствие:** неверный ответ AI или повреждённый запрос вызывает отказ, а длинный контекст расходует лишние ресурсы.
**Фикс:** схема запроса и ответа с пределами, нормализация до UI, 400 для ошибочного ввода; валидировать структуру, не «лечить» её приведениями TypeScript. Это уточнение известного долга, не отдельная повторная находка «нет zod».

### N10. Очистка чата скрывает ошибку удаления — [MEDIUM] [HIGH]

**Файл:** `src/components/AiAdvisor.tsx:154–165`.
Локальный чат очищается первым; результат Supabase delete не проверяется на `error`. Такие ошибки обычно возвращаются объектом, а не исключением.
**Последствие:** пользователь видит пустой чат, хотя сообщения остались в облаке.
**Фикс:** проверить `error`, очищать после подтверждения, сообщать отказ; блокировать конкурирующую отправку во время очистки.

### N11. Кеш не отделён по аккаунтам — [MEDIUM] [HIGH]

**Файл:** `src/pages/Index.tsx:65–67,105–107,371–379`.
Общие ключи localStorage; после выхода данные фильмов не очищаются. Новый аккаунт до успешного sync видит старую библиотеку.
**Последствие:** раскрытие истории следующему пользователю браузера, смешанный контекст при ошибке загрузки.
**Фикс:** кеш по user.id; на выходе/смене пользователя сбрасывать пользовательские state и незавершённые запросы. Локальный режим хранить отдельно.

### N12. Повторы проходят фильтр чата из-за разной нормализации — [MEDIUM] [HIGH]

**Файлы:** `supabase/functions/ai-chat/index.ts:476–493`, `movie-recommendation/index.ts:303–325`.
Чёрный список схлопывает пробелы, ответ — только trim/lowercase. Локально двойной пробел пропустил просмотренное в чат.
**Фикс:** один normalizeTitle на обеих сторонах сравнения. Главный подбор дополнительно защищён клиентским фильтром; нельзя объявлять его полностью неработающим.

### N13. Импорт искажает тип и молча отбрасывает записи — [MEDIUM] [HIGH]

**Файл:** `src/lib/fileParser.ts:31,168,185,232,255,313,327`.
JSON не допускает miniseries; XLSX понимает только TV_SERIES/MINI_SERIES, но не series/miniseries. JSON/CSV обрезаются до 5000 без предупреждения в результате.
**Последствие:** исчезнувшие строки, сериалы как фильмы, неверная дедупликация.
**Фикс:** единая нормализация типов, отчёт «принято/отклонено/обрезано»; проверки всех поддерживаемых форматов.

### N14. «Свежие вкусы» включают импорт без даты — [MEDIUM] [HIGH]

**Файл:** `src/lib/tasteProfile.ts:119–124`.
Проверяется лишь truthy watchedAt; дата 1970-01-01 из импорта проходит. Если новых оценок менее 30, остаток заполняется произвольной старой историей.
**Последствие:** промпт выдаёт недатированные предпочтения за недавние.
**Фикс:** исключить sentinel-дату, позднее хранить неизвестную дату явно. Локально воспроизведено.

### N15. Нет дедлайнов внешних запросов — [MEDIUM] [HIGH]

**Файлы:** `src/lib/globalRecommendation.ts:54`, `src/components/AiAdvisor.tsx:234`, `supabase/functions/ai-chat/index.ts:42,61,111,166`, `movie-recommendation/index.ts:131`.
Нет AbortSignal/общего срока; подбор повторяет и постоянные ошибки провайдера.
**Последствие:** длительный loading, повторные расходы при повторном действии пользователя; отмена UI не останавливает серверную работу.
**Фикс:** ограниченный бюджет времени; retries только для временных ошибок, без молчаливой смены платного провайдера.

## Покрытие остальных секций канона

- **Security:** в текущих файлах и 307 коммитах main поиск распространённых шаблонов приватных ключей/токенов совпадений не дал. Исторический .env действительно был: проверены только названия переменных и JWT role=anon; это публичный клиентский ключ, не service_role. Значения не публикуются. Это не исчерпывающий secret scanning.
- **RLS:** основные kino.user_movies/chat_messages имеют ownership policies; public views — security_invoker. Backup-таблицы без RLS, но SELECT у anon/authenticated отозван: не считать автоматически доступными. Отсутствие policies у rate_limits намеренно запрещает клиентский доступ к таблице.
- **CI:** нет workflow тестов; deploy без явных permissions, timeout, concurrency, фиксированной версии CLI; изменение config.toml не попадает в paths. Минимальный план: тестовый gate, contents:read, согласованный timeout и сериализация деплоя, учёт config.
- **SSOT/PWA:** `index.html:13` и VitePWA генерируют два manifest-link в собранном HTML. Оставить один источник manifest. Разные defaults провайдеров и нормализаторы размножены; объединять только при соответствующих исправлениях.
- **Архитектура:** UI → lib → Supabase/Edge разделены разумно. Index 982 строки совмещает auth, sync, импорт и модалки; AiAdvisor 512, сервер ai-chat 506. Выделить sync/auth при исправлении N06/N11, не переписывать весь проект. Три кандидата на удаление после проверки импортов: `src/App.css`, неиспользуемые `ui/dialog.tsx` и `ui/toggle.tsx`. Не удалялись.
- **Зависимости:** например recharts, react-hook-form, cmdk не используются приложением; QueryClientProvider установлен без useQuery/useMutation. Это обслуживание/установка, не доказательство включения всех пакетов в bundle.
- **Observability:** ошибки есть в console, но N10 их теряет; нет единого request-id и различения отказа rate-limit DB от исчерпанной квоты. Файловый logger в Edge/browser не обязателен: достаточно платформенных логов с request-id и безопасными причинами ошибок.
- **Windows:** deploy.ps1 содержит BOM; gitattributes задаёт CRLF. Сам PowerShell-скрипт не исполнялся. `git checkout main` не проверяет exit code; pull не ограничен --ff-only. Перед деплоем проверять ветку и соответствие origin/main.
- **UX/accessibility:** `RatingModal.tsx:18–34` — собственная модалка без dialog/focus trap/Escape; иконки чата без доступных названий, `WatchHistory.tsx:49` — кликабельный div без клавиатуры; `index.html:5` просит запрет масштабирования. Исправлять семантику без редизайна; iOS проверить отдельно.
- **Design system:** gitlink закреплён на 812c9eb, текущий main design-system — 798ef6c; различие не доказывает дефект дизайна. Визуальная сверка с preview не выполнена, автоматически обновлять submodule нельзя.
- **Meta/docs:** todo одновременно закрывает и вновь открывает историю про tombstones; lessons про обязательный fallback противоречит осознанному выбору провайдера в PR #75. Нужна одна актуальная формулировка решения, без новых PR на каждую заметку.

## Что осталось проверить в production

1. Связь Vercel с текущим SHA, реальные env, CORS allowlist, заголовки, PWA и iOS.
2. Доступность конкретных ID моделей в аккаунтах провайдеров, ключи и лимиты бюджета; не объявлять модели несуществующими только по памяти. Production ai-chat v36 и movie-recommendation v40 имеют verify_jwt=true и getUser; их исходники не побайтно равны репозиторию (в том числе форматирование/логирование), нужен воспроизводимый деплой.
3. Auth signup/anonymous settings, OTP-rate limits/CAPTCHA, экспозиция старой kino-схемы. В UI `AuthPanel.tsx:33,116` ещё принимает 6–7 цифр при задокументированном восьмизначном OTP.
4. Чистое восстановление БД, транзакционные тесты импорта, UI-сценарии с отказами сети. Табличные данные пользователя не выгружались.
5. Supabase Advisor также сообщает общепроектные настройки; проблемы соседнего Technical Language не включены как дефекты Kino.
