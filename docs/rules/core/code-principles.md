# Code Principles — работа с кодом

_Rule: always-on. Источник: AI_OS/SYSTEM.md §6._

## Простота и scope

- **Не добавлять фичи без запроса.**
- Не рефакторить «заодно» — заметил улучшение вне scope → сообщи, не трогай.
- Не создавать абстракции под гипотетическое будущее.
- **Простой код лучше «правильного».** Три похожих строки — ещё не абстракция; преждевременная абстракция дороже дубля.
- **DRY**: дублирующийся код выносить явно — три похожих строки уже сигнал (но не автоматически).

## Verification перед «готово»

- Прогнать тесты / CLI на **golden path + edge case**.
- Тайпчек ≠ работающая фича. Если UI — открыть в браузере и проверить визуально.
- Сравнить до/после если релевантно (для рефакторов, где функциональность должна остаться идентичной).
- Спросить себя: «одобрил бы это Senior Engineer в проде?»

## Безопасность (базовый уровень)

- **Никакого command injection**, path traversal, hardcoded secrets.
- Секреты — только в `.env` (в `.gitignore`) или GitHub Secrets / Supabase Vault.
- Внешние скрипты — с SRI (integrity).
- Проверка входа на границе системы (user input, external API). Внутренним вызовам доверяй.

## Правило «корень проблемы»

- Не хакать симптом — искать причину.
- Не временные фиксы, если можно фиксить корень.
- Явные решения лучше хитрых.
